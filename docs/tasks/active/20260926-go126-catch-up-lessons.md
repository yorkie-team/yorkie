# Go 1.26 catch-up — lessons

## `go fix ./...` only sees the default build

Run bare, `go fix` covers 44 files. With every tag
(`integration,bench,complex,fuzz,rgafuzz,starrocksrehearsal`) it covers 59, and
with `GOOS=linux GOARCH=amd64` added it covers 61: two test files are
`//go:build amd64` and are invisible on an arm64 laptop. A sweep that does not
set both is a sample, not a sweep.

## One pass is not a fixed point

`rangeint` turned `for i := 0; i < 10; i++` into `for i := range 10`, and only
then did `forvar` see the `i := i` inside as redundant. Re-run until
`go fix -diff` prints nothing.

## `reflect.TypeFor` is safe wherever `go fix` offers it

The #2058 lessons said the two amd64-only `reflect.TypeOf` calls would change
meaning under `TypeFor`. They do not: the analyzer only rewrites when the
argument's static type is concrete, and both are (`*backend.Backend`,
`*v1connect.UnimplementedYorkieServiceHandler`). The earlier judgement was
made without a 1.26 toolchain and without the `amd64` tag, so it never saw
what the tool would actually propose.

## A hand-written `rangeint` broke a test helper silently

#1348 rewrote `parseSimpleXML` in `test/complex` from a three-clause loop to
`for i := range len(s)`. The body advances `i` past a tag, which a three-clause
loop keeps and a range loop throws away, so `<p>` came out as `<p>`, `p`, `>`.
`getMergeRange` then indexed the wrong tokens and every merge case in the
complex lane has run against the wrong range since — while passing.

`go fix`'s `rangeint` refuses exactly this case; a person applying the same
rewrite by pattern did not. An AST scan for range loops that assign their key
or value found only this one and one deliberate reassignment in
`server/packs/pushpull.go`.

Rules:
- Prefer the analyzer to hand-applied rewrites; it checks the preconditions.
- A helper that shapes test inputs needs its own test, or a bug in it turns
  every test built on it into a false green.

## Self review, round 1 (correctness weighting)

Ten findings. Applied seven:

- `make modernize` read `[ -z "$(go fix -diff)" ]`, and a failed
  substitution inside `[ ]` is invisible to the exit status — a tree that did
  not compile read as "settled" and exited 0. The same trap `verify-modernize`
  had already guarded against, missed one target over. Rule: in shell, assign
  a substitution to a variable before testing it, every time.
- The apply loop's last pass was never checked, so a tree that settled on
  pass 3 reported failure.
- The hand-kept tag list would have let a new `//go:build` tag fall outside the
  gate — the exact blind spot this task started from. The list is now derived
  from the `//go:build` lines, with a hard error on negated tags and on any
  platform other than linux/amd64. Both logic changes moved into
  `scripts/go-fix.sh`, where they can be read.
- `slices.Sorted(maps.Keys(m))` grows from nil; the six CRDT marshal/attribute
  paths had a `make(..., 0, len(m))` for a reason. Now `slices.AppendSeq` onto
  a sized slice, then `slices.Sort`.
- goimports, fed `golang.org/x/exp` paths it had guessed and I rewrote by
  hand, left `"slices"` and `"maps"` in their own std groups in 16 files.
- `b.ResetTimer()` directly before a `b.Loop()` loop and `b.StopTimer()`
  directly after it are dead: `b.Loop` does both.
- `make verify` descriptions in CONTRIBUTING.md and CLAUDE.md, and the step
  count in ci-lane-reports.md.

While removing trailing `StopTimer`s I took one out of `BenchmarkRemoteApply`
that was *inside* the loop body — paired with a `StartTimer` two lines down —
because I located "the loop it follows" by the last `for` above it. Put back.
Rule: a timer call's position relative to a loop has to be read from the
braces, not from the nearest `for`.

Declined:

- `docs/tasks/README.md` not updated — yorkie's CLAUDE.md says the active
  README is hand-written and the index is regenerated by
  `scripts/tasks-index.sh` at archive time.
- Embedding `atomic.Int32` in `routineID`/`loggerID` — it would put `Add`,
  `Store` and `Swap` on the type's method set; the named field keeps `next()`
  the only way in.
- `parseSimpleXML` on non-ASCII or an unterminated `<` — the behaviour it had
  before #1348, and every input is a fixed ASCII literal. Known limitation.

## Self review, round 2 (design-fit weighting)

Two findings, both applied:

- `BenchmarkPresenceConcurrency` ended its loop body with `b.StopTimer()`.
  Under `for b.Loop()` that is fatal from the second iteration — 1.26 fails
  with "B.Loop called with timer stopped" — so all three sub-benchmarks died.
  Round 1's smoke test ran only two benchmarks, and a 1x run would not have
  caught it either: the check fires on the second `b.Loop()` call. Fixed with
  a `b.StartTimer()` after cleanup, then every benchmark in the repository run
  at `-benchtime=2x`. Rule: converting to `b.Loop` needs every converted
  benchmark run at least twice, and a body that stops the timer must leave it
  running.
- `scripts/go-fix.sh` treated `ignore` as a tag, so a conventional
  `//go:build ignore` generator (`package main`) would have broken the gate on
  correct code. `ignore` and `go1.N` are now skipped.

## Self review, round 3 (security/docs weighting)

`scripts/go-fix.sh` held up on shell safety. Four doc findings, all applied:

- The note under the ci-lane-reports lane table was inserted *above* the
  `test` row, which ended the table and dropped the most important lane from
  it. Markdown tables do not survive a paragraph in the middle.
- `run-lanes.mjs`'s header still said every lane replaced a step and that
  `make verify` was untouched — the two claims its own comment calls
  load-bearing.
- The three fixer prompts and the no-diagnosis fallback in
  `agent-iterate-ci.yml` still described `make verify` without the `go fix`
  check, so an agent facing a red `modernize` lane would hand-edit idioms
  instead of running `make modernize`. Rule: a new gate is not done until
  every prompt that describes the gate set names it and its fix command —
  grep the workflows for the old description, not just the docs.
- The todo and the sort commit message still described
  `slices.Sorted(maps.Keys(m))`, the form round 1 replaced.

Three rounds, the cap. Round 3's findings were documentation only; none
blocking.

## Review panel, round 1 (test adequacy)

One blocking finding, applied: `scripts/go-fix.sh` is the whole body of the
`modernize` lane, and the three rounds above rewrote its exit-status rules
twice — including the fail-open bug in round 1 — with nothing executing the
script. `scripts/test/go-fix.test.mjs` now pins all three branches of
`pending()` (clean, diff-with-non-zero-status, empty-with-non-zero-status),
the `|| true` on the applying pass, the 3-pass ceiling, the derived tag list
and the two hard errors, by putting a scripted `go` on PATH — the `Docs` job
that runs the suite is Node-only, and no real toolchain can be asked to report
"pending rewrites, non-zero status" on demand.

Each assertion was checked against a mutated script rather than trusted for
passing: making `pending()` fail open reds the two compile-failure cases,
reading the status alone reds three, and dropping `|| true` reds the apply
case. Rule: a test written for a gate that was already green proves nothing
until the gate is broken on purpose and the test goes red.
